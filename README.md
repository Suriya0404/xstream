# x-stream

A visual streaming-pipeline designer backed by Apache Flink SQL.

Draw a pipeline in the browser, click **Run**, and x-stream generates Flink SQL
on the fly, submits it to the Flink SQL Gateway, and streams results into
ScyllaDB and ClickHouse — all while ingesting live market data from Finnhub.

## Where Flink Jobs Live

x-stream does **not** use pre-compiled JAR files. Jobs are **Flink SQL** generated
at run-time. Here is the complete trail of where everything is stored:

### 1 — Pipeline graph → MySQL

When you save a pipeline in the UI, the node graph is written to MySQL:

| Table | Contents |
|---|---|
| `pipelines` | name, timestamps |
| `nodes` | node type (`kafka`/`scylladb`/`clickhouse`), label, canvas position, schema fields, per-node Flink SQL override |
| `edges` | source → target connections |
| `pipeline_runs` | run status, Flink job ID, timestamps |
| `pipeline_run_logs` | structured log lines per run |

### 2 — SQL generation → `backend/sql_parser.py`

When **Run** is clicked, `backend/services/pipeline_service.py`:

1. Topologically sorts the node graph (Kahn's algorithm).
2. Calls `generate_flink_sql(node, edges, all_nodes, config)` for each node in order.
3. Assembles a multi-statement SQL script:

```sql
SET 'parallelism.default' = '4';

-- Node: kafka-trades (kafka)
CREATE TABLE IF NOT EXISTS `kafka-trades` (
  `symbol` STRING,
  `price`  DOUBLE,
  ...
  `_kafka_ts` TIMESTAMP(3) METADATA FROM 'timestamp' VIRTUAL
) WITH (
  'connector' = 'kafka',
  'topic'     = 'finnhub-enriched',
  ...
);

-- Node: scylla-sink (scylladb)
CREATE TABLE IF NOT EXISTS `scylla-sink` ( ... ) WITH ( 'connector' = 'cassandra', ... );
INSERT INTO `scylla-sink` (`symbol`, `price`, ...) SELECT `symbol`, `price`, ... FROM `kafka-trades`;

-- Node: clickhouse-reports (clickhouse)
CREATE TABLE IF NOT EXISTS `clickhouse-reports` ( ... ) WITH ( 'connector' = 'jdbc', ... );
INSERT INTO `clickhouse-reports` (...) SELECT ... FROM `kafka-trades`;
```

### 3 — SQL submission → Flink SQL Gateway (port 8083)

`backend/flink_runner.py` (`FlinkSQLGateway`) submits each statement to the
SQL Gateway REST API:

```
POST  /v1/sessions              → create a session
POST  /v1/sessions/{id}/statements   → execute one DDL/DML statement
GET   /v1/sessions/{id}/operations/{op}/status  → poll until FINISHED
```

The **Flink job ID** returned by the INSERT statement is stored in
`pipeline_runs.flink_job_id` in MySQL.

### 4 — Job state → Docker volume

Flink checkpoints (fault-tolerance snapshots) are written to the
`flink-checkpoints` Docker volume, mounted at `/opt/flink/checkpoints/`
inside both the Job Manager and Task Manager containers.

```
flink-checkpoints/
└── <job-id>/
    └── chk-<n>/           # checkpoint snapshot files
```

### 5 — `flink-jobs/` directory

The `flink-jobs/` directory at the repo root is **currently empty**. It is a
placeholder for any future custom JAR-based Flink jobs. SQL-mode jobs (the
default) do not need files here.

### Summary

| Artefact | Where it lives |
|---|---|
| Pipeline graph (nodes, edges) | MySQL `pipelines` / `nodes` / `edges` |
| Generated Flink SQL | Built in-memory by `backend/sql_parser.py` at run-time |
| SQL submitted to Flink | Flink SQL Gateway session (ephemeral, in Job Manager process) |
| Active Flink job ID | MySQL `pipeline_runs.flink_job_id` |
| Checkpoint / state data | Docker volume `flink-checkpoints` → `/opt/flink/checkpoints/` |
| Run logs | MySQL `pipeline_run_logs` |
| Custom JAR jobs (future) | `flink-jobs/` |

## Quick Start

### Prerequisites

- Docker Desktop
- Node.js 18+
- Python 3.11+

### 1 — Configure secrets

```bash
cp .env.example .env
# Fill in ANTHROPIC_API_KEY and FINNHUB_API_KEY in .env
```

### 2 — Start everything

```bash
./scripts/start-sandbox.sh
```

This starts all infrastructure containers, the backend (with hot-reload), and
the Vite dev server. Open `http://localhost:5173`.

### 3 — Or start services individually

```bash
# Infrastructure
docker compose -f docker/docker-compose.yml up -d

# Backend
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

# Frontend
npm install
npm run dev

# Finnhub producer (requires FINNHUB_API_KEY in env or config.yaml)
cd producer
pip install -r requirements.txt
python finnhub_producer.py

# ScyllaDB consumer
python scylla_consumer.py
```

## Data Flow — Step by Step

1. **Finnhub producer** opens a WebSocket to `wss://ws.finnhub.io` and polls
   `GET /api/v1/quote` every 10 s. It publishes to three Kafka topics:
   `finnhub-trades`, `finnhub-quotes`, `finnhub-enriched`.

2. **ScyllaDB consumer** reads `finnhub-enriched`, batches up to 500 records
   or 1 s of data, and upserts to `xstream.finnhub_merged` using
   `execute_concurrent_with_args` (50 concurrent requests). A 1-minute log
   summary shows records/min, Kafka consumer lag, and ScyllaDB flush latency.

3. **UI → draw a pipeline**: add Kafka source nodes, ScyllaDB / ClickHouse
   sink nodes, connect them with edges, and optionally write per-node Flink SQL
   overrides.

4. **UI → Run**: the backend topologically sorts the graph, generates a Flink
   SQL script, and submits it statement-by-statement to the SQL Gateway.
   The Flink job reads from Kafka and writes to the configured sinks
   continuously until cancelled.

5. **UI → Stop**: calls `POST /api/pipeline/:name/stop`, which cancels the
   Flink job via `PATCH /jobs/:id?mode=cancel` and marks the run `cancelled`.

6. **Flink checkpoints** are written every 10 s (`EXACTLY_ONCE` mode) to the
   `flink-checkpoints` Docker volume, so jobs resume from the last checkpoint
   after a container restart.

## MySQL Data Model

```
pipelines ──< nodes
          ──< edges
          ──< pipeline_runs ──< pipeline_run_logs
```

| Table | Key columns |
|---|---|
| `pipelines` | `id`, `name`, `created_at`, `updated_at` |
| `nodes` | `id`, `pipeline_id`, `node_type`, `label`, `pos_x/y`, `flink_sql`, `properties` (JSON) |
| `edges` | `id`, `pipeline_id`, `source_id`, `target_id`, `source_handle`, `target_handle` |
| `pipeline_runs` | `id`, `pipeline_id`, `status`, `flink_job_id`, `started_at`, `finished_at` |
| `pipeline_run_logs` | `id`, `run_id`, `level`, `message`, `timestamp` |

## Logging

| Process | Log file | Rotation |
|---|---|---|
| `finnhub_producer.py` | `producer/logs/finnhub-producer.log` | 10 MB per file, 10 backups |
| `scylla_consumer.py` | `producer/logs/scylla-consumer.log` | 10 MB per file, 10 backups |
| FastAPI backend | stdout (structlog JSON) | managed by Docker / systemd |

Every 60 seconds the producer and consumer emit a summary:

```
2026-05-25 20:31:00  INFO  [scylla-consumer]  ── 1-min summary ──  kafka_read=1,234  scylla_written=1,230  kafka_errors=0
2026-05-25 20:31:00  INFO  [scylla-consumer]      kafka_lag:       avg=18.3ms  min=1.2ms  max=340.0ms  (n=1234)
2026-05-25 20:31:00  INFO  [scylla-consumer]      scylla_flush:    avg=42.1ms  min=11.0ms  max=198.5ms  (n=3)
```

Override log directory and rotation with env vars:

```bash
LOG_DIR=/var/log/xstream   # default: producer/logs/
LOG_MAX_BYTES=20971520     # default: 10485760 (10 MB)
LOG_BACKUP_COUNT=20        # default: 10
```

**ClickHouse write metrics** are available in the Flink Job Manager UI
(`http://localhost:8082`) under the job's task / subtask I/O metrics —
ClickHouse is written by the Flink JDBC connector, not a separate Python
process.

## Flink SQL Gateway Quick Reference

```bash
# List active SQL sessions
curl http://localhost:8083/v1/sessions

# List running Flink jobs
curl http://localhost:8082/jobs/overview

# Cancel a job
curl -X PATCH "http://localhost:8082/jobs/<job-id>?mode=cancel"

# Query ScyllaDB directly
docker exec -it xstream-scylladb cqlsh -e \
  "SELECT symbol, price, volume FROM xstream.finnhub_merged LIMIT 10;"

# Query ClickHouse directly
curl "http://localhost:8123/?query=SELECT+*+FROM+xstream.reports+LIMIT+10"
```
